**DHCPスコープの設計方針**: 全VLAN共通で **`.2` 〜 `.100` の99アドレス** を払い出す。`.101` 以降は静的IP・MACバインド用に予約する。範囲を揃えることで、どのVLANでも「100番までがDHCP、それ以降は固定」という単一のルールで判断できる。

**VLAN20/25のDHCPを保留にした理由**: サーバー機器は台数が少なく入れ替わりも稀なため、まずは各OS側で静的IPを直接設定する方式(方式①)で開始。将来的にRTX830のDHCP + MACバインド (`dhcp scope bind <scope> <IP> ethernet <MAC>`、方式②) へ統一予定。

## 設計変更 (2026-07-15): サーバー機器はRTX830に直結

当初はサーバー系(Node0/Node2)もスイッチ経由でVLANタグ付けする予定だったが、スイッチ↔RTX830間のトランクリンク(1Gbps 1本)にサーバーの大容量通信(NFS/Immich/Frigate/バックアップ)まで集約すると無線APやIoTの通信と帯域を奪い合う懸念があり、かつRTX830のLAN1に空きポートがあったため方針変更。

- **Node0**: RTX830に直結。**Proxmox側でVLANアウェアなブリッジ(vmbr)を組み、VLAN20とVLAN25のタグを自身で付与する必要がある**
- **Node2**: バックアップ専用でVLAN20のみのシンプルな用途のため、当初方針通りスイッチ経由(アクセスポート)

**理由**: RTX830のLAN1は物理4ポートが内部で1つのL2ドメインにブリッジされているため、「ポートごとに別VLANを自動割当」はできない (LAN分割機能とタグVLANは併用不可)。直結する機器は自分でVLANタグを付ける必要がある。

## RTX830 タグVLAN設定

```
vlan lan1/1 802.1q vid=20 name=VLAN20_server
ip lan1/1 address 192.168.20.254/24
vlan lan1/2 802.1q vid=25 name=VLAN25_AI
ip lan1/2 address 192.168.25.254/24
vlan lan1/3 802.1q vid=30 name=VLAN30_IoT
ip lan1/3 address 192.168.30.254/24
vlan lan1/4 802.1q vid=40 name=VLAN40_guest
ip lan1/4 address 192.168.40.254/24

dhcp service server
dhcp server rfc2131 compliant except remain-silent
dhcp scope 1 192.168.10.2-192.168.10.100/24
dhcp scope 3 192.168.25.2-192.168.25.100/24   # 現状未使用(VLAN25 DHCP保留中)
dhcp scope 4 192.168.30.2-192.168.30.100/24
dhcp scope 5 192.168.40.2-192.168.40.100/24

dns host lan1 lan1/1 lan1/2 lan1/3 lan1/4
dns service fallback on
dns server dhcp lan2
```

**VLAN10 (`vid=10`) をタグVLANサブインターフェースとして定義していない理由**: Port8のネイティブVLANが10のため、VLAN10のフレームはタグなしでRTX830に届く。タグなしフレームは既存の素の `ip lan1 address 192.168.10.1/24` が処理するため、`vlan lan1/x 802.1q vid=10` を別途作ると通信の乗らない「幽霊インターフェース」になる。

## VLAN間フィルター設計

### ポリシー表

| From \ To | VLAN10 | VLAN20 | VLAN25 | VLAN30 | VLAN40 | インターネット |
|---|---|---|---|---|---|---|
| VLAN10 | — | 全許可 | SSH(22)のみ | 拒否 | 拒否 | 許可 |
| VLAN20 | **pass-log (観察期間)** | — | 拒否 | 拒否 | 拒否 | 許可 |
| VLAN25 | 拒否 | 拒否 | — | 拒否 | 拒否 | 443+DNS(RTX宛)のみ ※一時的に80/NTPも許可中 |
| VLAN30 | 拒否 | 拒否 | 拒否 | — | 拒否 | 許可 |
| VLAN40 | 拒否 | 拒否 | 拒否 | 拒否 | — | 許可 |

### 設計上の要点

- 戻り通信はdynamicフィルターで処理 (VLAN10発→VLAN20/25への通信の返信のみ自動許可)。dynamicはICMP非対応のため、VLAN20→VLAN10のICMPのみ静的に双方向許可 (ping疎通確認用)
- 各VLANの最終passルールは `pass * * * * *` とし送信元を制限しない (DHCP DISCOVERの送信元は0.0.0.0のため、送信元制限すると新規端末がIP取得不能になる)。reject群が先に評価されるため隔離ポリシーは維持される
- VLAN25のみ最終行reject (DHCP不使用・静的IPのため問題なし)
- 管理アクセス制限: `httpd host lan1` / `telnetd host lan1` (IoT/ゲストVLANからRTX830の管理画面ログイン画面に到達できてしまう問題への対処)
