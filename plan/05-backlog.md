## 複合機・キャスト機器のVLAN配置 — 当面VLAN10、将来VLAN30へ移行

**決定日**: 2026-07-15

### 現状
複合機 (Canon MF260) ・キャスト機器 (Apple TV / Chromecast / スマートTV等) は **VLAN10 (メイン) に収容**する。

### 理由
- RTX830はmDNSリピーター機能を持たず、これらをVLAN30に置くと機器発見 (AirPrint/AirPlay/Cast) がVLANを越えられない
- キャストは**プル型** (スマホが機器に再生指示 → 機器が自らサーバーへ取得しに行く) のため、キャスト機器がVLAN10にいれば発見は同一VLAN内で完結し、メディア取得もVLAN10→VLAN20の既存許可 (10110) で通る。mDNSリピーター不要
- ホームラボ建設中の現段階では、ピンホールACL + リフレクターの複雑化に見合わない

### 移行条件
VE4 (Pi-hole LXC) が稼働し、**Avahi (mDNSリフレクター) を同居**させられるようになったら、まとめてVLAN30へ移す。

### 移行時に必要な作業
1. VE4にAvahiリフレクターを導入 (VLAN10⇄VLAN30間のmDNS転送)
2. 対象機器のIP固定: `dhcp scope bind 3 192.168.30.x ethernet <機器MAC>`
3. **印刷用ピンホール**: VLAN10→複合機 (TCP 631/9100/515) の許可を `10130 reject` より前に挿入、lan1/4のout側にdynamicフィルター追加
4. **スキャン用ピンホール**: 複合機→VLAN20のSMB (TCP 445) 許可を `10420 reject` より前に挿入
   `ip filter 10411 pass 192.168.30.5 192.168.20.0/24 tcp * 445`
5. **キャスト用ピンホール**: キャスト機器→VLAN20のImmich等 (TCP 2283など) の許可を追加。スマホ→キャスト機器の制御通信 (TCP 8008/8009等) の許可も `10130 reject` より前に挿入

### 参考 (定石)
企業ではプリンター専用VLAN + ピンホールが主流だが、専任管理者によるACL保守が前提。家庭では「有名メーカー機器はメインVLAN許容」も一般的な割り切りであり、**mDNS越えの仕組み(リフレクター)を持ってから分離する2段階**が現実的。

## Coral USB TPU (Frigate検出専用) — 保留

- 2019年発売と型は古いが、Frigateは実用的な限りサポート継続の方針であり動作は可能
- ただしGoogleのメンテナンスが停止気味で、新しいLinuxカーネルとの互換性はコミュニティ対応頼み (公式には新規導入の第一推奨ではなくなっている)
- **Proxmox環境での注意点**: USB Coralは未初期化時 `1a6e:089a` → 初期化後 `18d1:9302` とデバイスIDが変化するため、VM側で**両方をマッピング**する必要あり。USBハブ経由は不安定になりやすく**直結推奨**
- **導入判断基準**: VRAM使用量が頻繁に4GB上限に張り付くようになったら検討

## GPU 2枚構成 (GTX1650追加) — 却下

- PCIE3スロット (x4動作) に増設可能、電源容量も問題なし
- メリット: GPU1をImmich専用、GPU2をOllama専用に分離しVRAM競合を根本解消
- **却下理由**: 電力対性能比が悪く、中古RTX3060 12GB 1枚の方がコスパ・演算力ともに優位。→ RTX3060導入方針へ統合 ([`04-gpu-ai.md`](04-gpu-ai.md))

## Immich処理優先度によるFrigate検出の一時停止 — アイデアメモ

Immichの重い処理 (大量アップロード時のML実行等) が走る間、Frigateの**物体検出 (detect) のみ**を一時停止し、**録画 (record) は継続**させる仕組み。

**技術的には実現可能**: Frigateは `detect` と `record` が独立roleのため、API (`PATCH /api/config`) または MQTT (`frigate/<camera_name>/detect/set`) で検出のみON/OFF制御できる。

**実装方法の選択肢**
1. 自前スクリプト: ImmichのジョブキューをAPI経由でポーリング → 閾値超過でFrigateにMQTT/API送信、完了後に復帰
2. Home Assistant連携: HAのAutomationエディタ (GUI) でトリガー(Immich負荷) → アクション(MQTT経由でFrigate detect OFF/ON)

**現段階**: 実装は保留、設計メモとして記録のみ。
