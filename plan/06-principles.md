## 全体方針

- **アーキテクチャは実測・検証を経てから確定させる。** 先走った投資をしない
- **低メンテナンス性を優先する。** レイヤーを増やす選択には、それに見合う理由を要求する
- **段階的に締める。** 「理屈上不要なはず」の通信は、いきなり遮断せず一定期間ログを取って実証してから締める
- **決定は理由とセットで記録する。** 却下した案とその理由も残す

## Proxmox / 仮想化

- **6TB HDDのパススルー方式はIOMMUグループ確認まで決定を保留する**。民生チップセット (B450) ではグループが粗い可能性がある → **実測結果 (2026-07-21)**: B450M Pro4では6TB HDD側SATA (`02:00.1`) とUSB 3.1 (`02:00.0`) が同一グループ14。ディスク単位分離は不可で、コントローラ単位パススルー + TrueNAS VMに決着 ([`03-proxmox.md`](03-proxmox.md))
- **`pcie_acs_override` はハードウェアの分離保証を無効化する回避策**。安易に使わない。今回は不要だった (グループ14をそのまま渡せた)
- **AMD環境ではIOMMUはBIOS有効化だけでグループ生成される**。`amd_iommu=on` のカーネルパラメータ明示は必須ではない (Intelの `intel_iommu=on` とは事情が異なる)。ただし念のため付与しておくのは無害
- **vfio-pciのバインドには `softdep` が要る**。`options vfio-pci ids=...` だけでは不十分。`ahci`/`xhci_hcd` は初期化が早く (起動1.2秒台)、後からロードされる `vfio-pci` (5秒台) が既に掴まれたデバイスを奪い返せない。`softdep ahci pre: vfio-pci` / `softdep xhci_pci pre: vfio-pci` で「先にvfio-pciをロードさせる」ことで解決する。`dmesg` のタイムスタンプでロード順序を確認できる
- **同一ドライバが複数コントローラを扱う場合、ドライバ全体のブラックリストは不可**。今回 `ahci` は渡す側 (`02:00.1`) と残す側 (`09:00.2`) の両方を扱うため、`ids=` で対象を限定しつつ `softdep` で順序制御する方式が正解
- **Windowsリテールライセンスは明示的な認証解除なしでVM移行可能**
- **Proxmoxネイティブ NFS (ホストZFS + 特権LXC) を TrueNAS VM より優先**。レイヤーとRAMオーバーヘッドが減るため。ただしコントローラ単位のパススルーが必要になればTrueNAS VMへ回帰する → 今回は回帰条件が成立しTrueNAS VMを採用

## GPU / LLM

- **GPUリソース競合がNode0の中心的制約**。Frigate/Immich/Ollamaが常に競合しうる前提で設計する
- **NVLinkはRTX 3090/3090 Tiのみ。** RTX 3060の2枚構成でVRAMは統合されず、PCIe層でのレイヤー分割になる
- **VRAM要件はモデル本体 + KVキャッシュで見積もる。** 長コンテキストほどKVキャッシュが支配的
- **`OLLAMA_KEEP_ALIVE=0`** で推論後にVRAMを解放し、GPUを低消費電力アイドルへ戻す

## ネットワーク (RTX830 / YAMAHA)

- **RTX830のLAN1は4ポートが内部で1つのL2ドメイン。** ポート単位で別々のVLANを自動割当することはできない (タグVLANとLAN分割機能は併用不可)。直結する機器側でVLANタグを付与する設計が必要
- **タグVLANとネイティブVLANの整合性に注意。** スイッチのトランクポートでネイティブ(untagged)指定したVLANは、RTX830側でもタグなしの素のインターフェース (`ip lan1 address`) で受ける。タグ付きサブインターフェースを重複して作ると、トラフィックが来ない「幽霊インターフェース」になる
- **`multi-session=off` の落とし穴。** 古いセッションが `login-timer` のタイムアウトを迎えるまで新規ログインを拒否する (401エラー)。接続経路を変更した直後にログインできない場合、まず数分待ってから再試行する
- **`dhcp scope bind` は `ethernet` キーワードを明示する。** YAMAHAルーターは初期設定でMACアドレスよりClient Identifierによる識別を優先するため、省略すると固定割り当てが効かないことがある
- **`httpd host` / `telnetd host` はCIDR表記 (`/24`) を受け付けない。** インターフェース名 (`lan1`) またはハイフン範囲指定で書く

## ファイアウォール設計

- **secure filterの最終passで送信元を制限しない。** DHCP DISCOVERは送信元0.0.0.0のため、送信元制限付きの最終ルールだと新規端末がIP取得不能になる。最終行は `pass * * * * *` とし、reject群を先に評価させる
- **静的フィルターはステートレス。** 送信元・宛先だけで判定するため、「クライアントが開始した通信への返信」も見た目上は「サーバー発の通信」として拒否される。戻り通信は dynamicフィルター (`ip filter dynamic`) で処理する
- **dynamicフィルターはICMP非対応。** TCP/UDP系のみ追跡可能。pingを通したい経路はICMPの静的な双方向許可が別途必要
- **サブネット宛rejectだけではルーター自身の管理画面を守れない。** 各VLANから見たゲートウェイは自VLANサブネット内のため、VLAN間rejectに一致しない。`httpd host` / `telnetd host` でサービス側の受け付け元を制限する
- **締める前に `pass-log` で観察する。** rejectでいきなり締めると「静かに何かが壊れる」事故を招く

## 無線 (WLX222)

- **設定保存 ≠ 反映。** 設定変更後は必ずRTX830のLANマップ経由でWLX222自身のGUIを開き、「設定」タブ → 「設定送信」 → 「送信」を実行しないと実機に反映されない
- **IoT用SSIDはWPA2-PSK単独を推奨。** WPA2/WPA3混在モードだとPMF (Protected Management Frames) が強制され、古いIoT機器が「SSIDは見えるが接続できない」状態になりやすい

## メモリ / ハードウェア検証

- **Ryzen 2000番台 + B450 + 4枚フル実装では定格クロックが通らないことがある。** 4ランク実装でIMC (CPU内蔵メモリコントローラ) の負荷が増し、2枚では安定する周波数/タイミングが4枚では不安定になる。対処は周波数を落とす (今回 DDR4-2933 CAS22 → 2400 CAS17)。用途がメモリ帯域にシビアでなければ迷わず落とす。詳細な検証記録は [`01-hardware.md`](01-hardware.md)
- **ASRock B450M Pro4 のメモリスロットは A2/B2 が優先。** マニュアルも1枚なら A2、2枚なら A2+B2 を指定。A1/B1 の使用は不安定報告が多い。物理スロット並びはCPU側から A1, A2, B1, B2
- **memtest86+ の「誤検出」と「実不良」は挙動で見分ける。**
  - *誤検出の疑いが濃いパターン*: エラーが毎回**寸分違わず同じ**(同じ経過時間・同じテスト番号・同じ低位アドレス0-4MB付近)・1件のみ。低位アドレスはBIOS/SMM/ACPIの予約領域と重なり、コミュニティ版 memtest86+ (無印の商用 MemTest86 とは**別物**) はこの領域で誤検出を起こしやすい
  - *実不良/信号品質問題の疑いが濃いパターン*: エラーが**メモリ全域に分散**・**周を重ねるごとに累積increase**・ビット単位で毎回異なる。今回A1スロットで7周Errors:11まで増加したのはこれ
  - **切り分けの定石**: 容量・メーカーが揃うペアを推奨スロット (A2/B2) に入れて基準を作り→スロットを変える/枚数を変えることで「スティック個体か・スロットか・枚数(電気的負荷)か」を分離する
- **長時間・複数周回して初めて「安定」と言える。** 1周Passでは間欠エラーを見逃す。今回の最終確認は約11時間・4周・Errors:0。間欠故障は1周目を平気で通過することがある

## 電源 / UPS

- **長期保管されたSLAバッテリーはサルフェーションにより不可逆的に劣化する。** 「未使用」表記は稼働時間を保証しない
- **アクティブPFC電源には正弦波出力のUPSが必須**
- **停電は「いつか」ではなく既に起きた。** 2026-07-20、構築中に約5秒の停電でNode0が電源断。ZFSは無傷で復旧したが、これはVM本格稼働前だったのが幸い。UPS未導入のまま本番運用に入らない

## 用語メモ

| 用語 | 意味 |
|---|---|
| パススルー | PCIeデバイス等をホストではなく特定のVMに直接割り当てる仕組み |
| IOMMU | デバイスをVMに安全に割り当てるためのメモリ管理機構。パススルー可否・粒度を左右する |
| IOMMUグループ | IOMMUが分離可能と判断するデバイスの最小単位。グループ内のデバイスは分割してVMに割り当てられない |
| ACSオーバーライド | IOMMUグループを人為的に細分化するカーネルパラメータ。分離保証を犠牲にする |
| リバースプロキシ | 複数の内部サービスを単一のドメイン/ポートで外部に公開する中継サーバー |
| VLANアウェアブリッジ | Proxmoxのブリッジ設定。ゲスト/ホスト自身がVLANタグを扱えるようにする |
| ネイティブVLAN | トランクポート上でタグを付けずに流すVLAN。untagged VLANとも |
| QDevice | Proxmoxクラスタの投票者を1つ追加する軽量デーモン。偶数ノード構成のクォーラム問題を解決する |
| KVキャッシュ | LLM推論時にAttentionのKey/Valueを保持する領域。コンテキスト長に比例してVRAMを消費する |
| サルフェーション | 鉛蓄電池の極板に硫酸鉛が結晶化して蓄積する現象。容量が不可逆に低下する |
